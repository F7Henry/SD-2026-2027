EXPLICAÇÃO DO LEADERBOT

FUNCIONAMENTO GERAL DO BOT
O LeaderBot é uma aplicação Java que utiliza a biblioteca JDA para comunicar
com a API do Discord. Depois de arrancar, mantém uma ligação ao Discord e
fica à espera de eventos, como comandos slash ou mensagens recebidas.

Quando um utilizador executa um comando, o Discord envia uma interação para
o bot. O LeaderBot identifica o comando, valida as permissões e os argumentos
e envia uma resposta provisória. Neste sprint, os comandos ainda não executam
as operações definitivas de arquivo, réplicas ou recuperação.

TOKEN DO BOT
DISCORD_TOKEN é o token secreto da aplicação Discord. Funciona como uma
credencial que permite ao programa autenticar-se como o bot e estabelecer a
ligação ao Discord.

O token não deve ser colocado no código, no README, em imagens ou num commit.
É definido como variável de ambiente apenas na sessão em que o bot é
executado. Se o token for divulgado, deve ser regenerado no Discord Developer
Portal.

ID DO SERVIDOR
DISCORD_GUILD_ID identifica o servidor de teste onde o bot foi instalado.
Este valor permite ao programa encontrar o servidor correto e registar nele
os comandos slash.

O LeaderBot guarda este ID na própria instância. Antes de tratar um comando
ou uma mensagem, compara o servidor do evento com o ID configurado. Se forem
diferentes, o evento é ignorado. Assim, o bot não responde no servidor antigo
nem noutros servidores onde ainda esteja instalado.

FLUXO DE ARRANQUE
1. O programa lê DISCORD_TOKEN e DISCORD_GUILD_ID.
2. Cria uma ligação autenticada ao Discord.
3. Regista o LeaderBot como listener de eventos.
4. Espera até a ligação estar pronta.
5. Confirma que o servidor configurado é acessível.
6. Regista os comandos no servidor de teste.
7. Remove os comandos dos outros servidores onde o bot esteja instalado.
8. Fica em execução à espera de comandos e mensagens.

Para executar no Windows PowerShell:
$env:DISCORD_TOKEN = "token-local-do-bot"
$env:DISCORD_GUILD_ID = "id-do-servidor-de-teste"
.\gradlew.bat run

O token e o ID definidos desta forma ficam disponíveis apenas na sessão
atual do PowerShell. No fim, podem ser removidos com:
Remove-Item Env:\DISCORD_TOKEN
Remove-Item Env:\DISCORD_GUILD_ID

Para executar no Windows CMD:
set DISCORD_TOKEN=token-local-do-bot
set DISCORD_GUILD_ID=id-do-servidor-de-teste
gradlew.bat run

No CMD, as variáveis ficam disponíveis apenas enquanto essa janela estiver
aberta. Para as limpar antes de fechar a janela, usar:
set DISCORD_TOKEN=
set DISCORD_GUILD_ID=

package tpf;
Coloca a classe no pacote tpf.

IMPORTS
Os imports carregam classes da biblioteca JDA, usadas para:
- ligar o programa ao Discord;
- criar e registar comandos;
- receber mensagens e interações;
- consultar membros, papéis e canais.

LeaderBot extends ListenerAdapter
Define o bot como um listener de eventos. A classe pode reagir a comandos slash e a mensagens recebidas.

CONSTRUTOR
O construtor recebe o DISCORD_GUILD_ID e guarda-o na instância do bot.
Os métodos que tratam eventos usam esse valor para aceitar apenas eventos
provenientes do servidor configurado.

CONSTANTES
ARCHIVE_CHANNEL guarda o nome do canal monitorizado: arquivo.
ADMIN_ROLE guarda o nome do papel necessário para comandos administrativos: admin-arquivo.

MÉTODO main
1. Lê DISCORD_TOKEN e DISCORD_GUILD_ID das variáveis de ambiente.
2. Cria a ligação ao Discord usando o token.
3. Regista LeaderBot como listener.
4. Espera até o bot estar pronto.
5. Confirma que o servidor indicado existe e é acessível.
6. Regista os sete comandos no servidor de teste:
   - /registar, com o texto;
   - /estado;
   - /config, com operacao e n;
   - /recuperar, com de e ate;
   - /replica-token;
   - /replica-remover, com id;
   - /rajada, com n e intervaloms.

Os limites definidos com setRequiredRange fazem com que o Discord rejeite valores fora do intervalo permitido antes de executar o comando.

onSlashCommandInteraction
É chamado quando alguém utiliza um comando slash.
1. Confirma que o comando veio do servidor configurado.
2. Se veio de outro servidor, ignora o evento.
3. Obtém o nome do comando.
4. Verifica se o comando exige administrador.
5. Se o utilizador não tiver o papel correto, envia uma resposta privada e termina.
6. Caso contrário, usa switch para escolher o tratamento correspondente.
7. Cada comando responde provisoriamente, repetindo os argumentos recebidos.

onMessageReceived
É chamado quando uma mensagem é enviada.
1. Ignora mensagens enviadas por bots, evitando respostas repetidas.
2. Confirma que a mensagem veio do servidor configurado.
3. Se veio de outro servidor, ignora o evento.
4. Confirma que o canal é de texto.
5. Compara o nome do canal com arquivo.
6. Só responde quando a mensagem foi enviada nesse canal.

Mensagens noutros canais são ignoradas.

REMOÇÃO DE COMANDOS DOS SERVIDORES ANTIGOS
No arranque, o programa percorre os servidores onde o bot está instalado.
Para cada servidor diferente do DISCORD_GUILD_ID, atualiza os comandos com
uma lista vazia. Isto remove os comandos antigos desses servidores e deixa-os
disponíveis apenas no servidor configurado.

handleConfig
Obtém o valor de n e verifica se é válido. Se for menor que 1, envia uma mensagem de erro; caso contrário, responde com uma confirmação provisória.

handleRecovery
Obtém os valores de e ate. Se de for maior que ate, o intervalo é inválido e o comando é recusado. Caso contrário, envia uma resposta provisória com os dois valores.

requiresAdmin
Indica quais comandos exigem o papel admin-arquivo:
- /config;
- /replica-token;
- /replica-remover;
- /rajada.

hasAdminRole
Recebe o membro que executou o comando, consulta os papéis desse membro e verifica se algum tem o nome admin-arquivo.

requiredEnvironment
Lê uma variável de ambiente. Se ela não existir ou estiver vazia, lança uma exceção para impedir que o bot arranque mal configurado.

quote
Coloca o texto entre crases para aparecer formatado no Discord e escapa crases que já existam dentro do texto.
